Section 1 — Databricks Intelligence Platform (6%)

⚡ Must-know
  • Lakehouse = open storage (Delta Lake) + warehouse reliability + one governance layer (Unity Catalog). Databricks SQL = the warehousing service; SQL warehouses = its compute.
  • Control plane = web app, jobs, notebooks (stored here, encrypted), metadata. Your data and classic clusters are NOT in it; code EXECUTES in the compute plane.
  • Serverless job compute = scheduled jobs with no pre-warming or idle cost · All-purpose = interactive · SQL warehouse = BI/SQL (bigger = lower latency) · Classic compute / Pro SQL warehouse = private or on-prem networks · Pools = faster start · Autoscaling = variable load · Spot = cheaper, retryable batch only.
  • %run shares variables; dbutils.notebook.run takes parameters and returns a value but shares nothing. SQL named parameters use :name.
  • Unity Catalog needs SQL warehouses or classic compute in Standard/Dedicated access mode (DBR 11.3 LTS+); "No isolation shared" is not supported.

What the exam expects

  • Explain the value of the lakehouse.
  • Control plane vs compute plane.
  • Pick the right compute.
  • Photon, Liquid Clustering, predictive optimization.
  • Notebooks, dbutils, Databricks Connect.

1.1 The lakehouse and the Data Intelligence Platform

A data lake stores raw files cheaply but lacks transactions and governance. A data warehouse gives fast, governed SQL but is expensive and closed. The lakehouse keeps data in open formats in your own storage, with Delta Lake adding ACID, schema enforcement and time travel, and Unity Catalog adding governance. Storage and compute are decoupled. Databricks SQL is the warehousing service.

💡 Plain English: If a question asks for the "value" of the platform, look for: unified, open formats, single copy of data, decoupled storage and compute, one governance model.

Section 2 — Data Ingestion and Loading (21%)

⚡ Must-know
  • COPY INTO = SQL, batch, idempotent (skips already-loaded files), thousands of files. force = true reloads everything; FORMAT_OPTIONS ('modifiedAfter' = ts) loads only recently modified files.
  • Auto Loader (cloudFiles, Structured Streaming) = incremental, millions of files, schema evolution. checkpointLocation = progress (exactly-once); cloudFiles.schemaLocation = schema. pathGlobFilter = only matching files (e.g. *.jpg); cloudFiles.allowOverwrites = re-ingest re-uploaded files.
  • Schema modes: addNewColumns (default: fail, then restart with new cols – needs schemaLocation), rescue (_rescued_data, never fails), failOnNewColumns, none.
  • trigger(availableNow=True) = all new data, then stop. processingTime="30 seconds" = micro-batch every 30 s. JSON/CSV infer as STRING unless cloudFiles.inferColumnTypes. Directory listing = simplest; file notifications = huge volumes / fewer LIST calls (still backfills existing files).
  • SaaS/database (incl. Snowflake, PostgreSQL CDC) with minimal code → Lakeflow Connect managed connector (one per source). Kafka → Structured Streaming format("kafka"). Plain JDBC = batch only.

What the exam expects

  • Choose between COPY INTO, Auto Loader, Lakeflow Connect, partner connectors and notebook-based ingestion (JDBC/ODBC, REST).
  • Know Auto Loader syntax, options, schema inference and evolution, and triggers.
  • Load data from cloud object storage and Unity Catalog volumes.
  • Ingest structured, semi-structured (JSON, nested) and unstructured data.
  • Create tables with CTAS and read_files().

2.3 COPY INTO

COPY INTO loads files into a Delta table and remembers which files it loaded, so re-running only picks up new files (idempotent). Ideal for scheduled batch loads of thousands of files. It tracks files, not rows – it does not de-duplicate the same record arriving in two files (use MERGE for that).

COPY INTO main.bronze.orders
FROM '/Volumes/main/raw/landing/orders/'
FILEFORMAT = CSV
FORMAT_OPTIONS ('header' = 'true', 'inferSchema' = 'true')
COPY_OPTIONS ('mergeSchema' = 'true');

-- Only files matching a pattern / modified after a timestamp
COPY INTO target_table FROM 'abfss://logs@staging.dfs.core.windows.net/'
FILEFORMAT = JSON
PATTERN = '2026-10-*.json'
FORMAT_OPTIONS ('modifiedAfter' = '2026-10-01 00:00:00');

-- Reprocess everything (breaks idempotency)
COPY_OPTIONS ('force' = 'true');

2.4 Auto Loader

Auto Loader is a Structured Streaming source called cloudFiles. It discovers new files, processes each exactly once by tracking discovered files in its checkpoint, scales to millions of files, and handles schema inference and change.

(spark.readStream
   .format("cloudFiles")
   .option("cloudFiles.format", "json")
   .option("cloudFiles.schemaLocation", "/Volumes/main/raw/chk/events_schema")
   .option("cloudFiles.inferColumnTypes", "true")
   .option("cloudFiles.schemaEvolutionMode", "addNewColumns")
   .load("/Volumes/main/raw/landing/events/")
 .writeStream
   .option("checkpointLocation", "/Volumes/main/raw/chk/events")
   .trigger(availableNow=True)
   .toTable("main.bronze.events"))

Schema evolution modes

ModeBehaviour when a new column appears
addNewColumns (default)Stream fails with UnknownFieldException, stored schema updated; on restart the new nullable column is included (older rows NULL). Existing types never change.
rescueSchema never evolves; new/mismatched fields go into _rescued_data. Never fails.
failOnNewColumnsFails and stays failed until the schema is updated or the file removed.

2.5 read_files() and CTAS

read_files() reads files with options; combined with CTAS it creates a Delta table in one statement (schema inferred, no manual column types). With STREAM inside a pipeline it behaves like Auto Loader.

CREATE OR REPLACE TABLE main.bronze.customers AS
SELECT *, _metadata.file_name AS source_file, current_timestamp() AS ingested_at
FROM read_files('/Volumes/main/raw/landing/customers/', format => 'csv', header => true);

-- External table over CSV files
CREATE TABLE my_table (col1 STRING, col2 STRING)
USING CSV OPTIONS (header = 'true', delimiter = ';') LOCATION '/path/input';

-- Direct query works for JSON/Parquet; CSV this way can't take options
SELECT * FROM json.`/Volumes/analytics/events/source_files/transactions.json`;

The hidden _metadata column gives file_path, file_name, file_size, file_modification_time (older code: input_file_name()).

2.6 Lakeflow Connect

Managed connectors – SaaS (Salesforce, Workday, ServiceNow…) and databases (SQL Server, PostgreSQL, MySQL, Snowflake…) – are low-code, fully managed pipelines on serverless compute, governed by UC. Setup: UC connection (credentials) → destination catalog/schema → schedule and notifications. First run is a full load; later runs ingest only changes (incremental / CDC). Standard connectors (Auto Loader, Kafka, SFTP…) need you to write more logic.

💡 Plain English: Managed connector = "Databricks runs the whole pipeline from an app or database". Auto Loader, COPY INTO, CTAS and Databricks Connect are NOT managed ingestion connectors.

3.2 Delta Lake – how it works

A Delta table = Parquet data files + transaction log _delta_log (numbered JSON commits listing files added/removed, plus Parquet checkpoints every 10 commits). Readers use the log to know which files make up a version → ACID and time travel. ACID does not require Unity Catalog. A Delta table can be a streaming source and sink.

DESCRIBE HISTORY main.silver.orders;     -- versions, operation, user, timestamp (30 days by default)
DESCRIBE DETAIL  main.silver.orders;     -- location, format, numFiles, sizeInBytes
DESCRIBE EXTENDED main.silver.orders;    -- columns + table properties
DESCRIBE SCHEMA main.silver;             -- = DESCRIBE DATABASE: name, comment, LOCATION

SELECT * FROM main.silver.orders VERSION AS OF 2;
SELECT * FROM main.silver.orders TIMESTAMP AS OF '2026-10-20T08:00:00';
RESTORE TABLE main.silver.orders TO VERSION AS OF 2;
UNDROP TABLE main.silver.orders;
ALTER TABLE main.ext.device_logs SET MANAGED;      -- UNSET MANAGED to roll back
OPTIMIZE main.silver.orders;                       -- compact small files
VACUUM main.silver.orders;                         -- delete unreferenced files > 7 days old
⚠ Exam trap: VACUUM breaks time travel past retention; it does not delete the log or current data, leaves newer files alone, and does not compact (that is OPTIMIZE).

Section 6 — Troubleshooting, Monitoring and Optimization (10%)

⚡ Must-know
  • Skew = a few tasks/partitions far bigger/slower than median & 75th percentile → AQE skew split, salting, isolate hot keys, Liquid Clustering. Evenly spread metrics with small GC = a normal stage.
  • Shuffle = big Shuffle Read/Write → broadcast the small table (F.broadcast; threshold in BYTES), filter early, tune spark.sql.shuffle.partitions.
  • Spill / OOM / ExecutorLostFailure in a wide transformation → more executor memory + more shuffle partitions (more cores makes it worse); memory-optimised nodes.
  • Liquid Clustering (CLUSTER BY (a, b) / AUTO – keys chosen by predictive optimization from query patterns) reduces data scanned; replaces partitioning + ZORDER. Predictive optimization = auto OPTIMIZE/VACUUM/ANALYZE (not ZORDER).
  • Driver OOM after collect()/toPandas() → increase spark.driver.memory or don’t collect. OPTIMIZE/ZORDER are CPU-heavy → compute-optimised nodes.

Section 7 — Governance and Security (15%)

⚡ Must-know
  • Unity Catalog = centralised governance across workspaces/clouds: Metastore → Catalog → Schema → Table/View/Volume/Function/Model; catalog.schema.object; audit + lineage built in.
  • Read a table: USE CATALOG + USE SCHEMA + SELECT (USE privileges only let you traverse – no data, no create). SELECT on a SCHEMA = all existing AND future tables in it. MODIFY = insert/update/delete.
  • Grant to groups (names with hyphens in backticks) or service principals (application ID in backticks). GRANT ALL PRIVILEGES ON TABLE t; REVOKE ALL PRIVILEGES … FROM g = clean slate (DENY is legacy Hive). Catalog Explorer grants take effect immediately; owners changed on the object’s page.
  • Column mask: ALTER TABLE t ALTER COLUMN c SET MASK fn. Row filter: ALTER TABLE t SET ROW FILTER fn ON (col). Both SQL UDFs using is_account_group_member. Views run with the owner’s rights.
  • ABAC: one tag-based policy (CREATE POLICY … MATCH COLUMNS hasTagValue('pii','credit_card') AS cc ON COLUMN cc) applies to all current and future tagged objects.
